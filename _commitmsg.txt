fix(语音): 修按住说话的竞态 + 加无麦克风的兜底提示

【实测结论：代码全链路正确，卡在模拟器没有麦克风】

日志证据（每一步都验证到了）：
  权限   ATM: GetSelfPermissionState MICROPHONE status: 0
  引擎   AI_TEXT: verify asrEngineOptions [zh-CN, online:1.00, short]
  开始   AsrEntryManager: calling startListening
         ReportCoreManager: result_code 0, message success
  界面   截图显示「正在听…」+ 按钮变红
  结束   Handle TouchUp -> calling finish function
         FinishRecognizerSync: Finish result code: 0

但：audioTimeLong 为 0        -> 录到的音频长度是 0
     /proc/asound/cards 为空  -> 模拟器无音频输入设备
     -> 引擎收不到音频，不产生 onResult，界面无文字

这是模拟器的硬件限制，不是代码问题。

【修掉的两个真 bug】

1. 「按住说话」的竞态
   startVoice() 里 requestMic() 是异步的（首次会弹权限窗），
   this.listening = true 要等它返回才置位；
   而用户往往在弹窗期间就松手了，
   此时 stopVoice() 里的 if (!this.listening) return 直接挡掉，
   表现为「松手没反应」。
   修法：加 released 标记记住松手意图，启动完成后自己收尾。

2. 按钮从「按住」改成「点按」
   按住式需要 Down/Up 配对，模拟器上用鼠标很难操作。

【新增兜底】
设备没麦克风时引擎不会回调，界面会永远卡在「正在听…」。
stopVoice 后等 2.5 秒，若没识别到内容就给提示
「没听到声音——模拟器通常没有麦克风，可以打字」。

【顺带发现：热词导致引擎创建失败】
配 79 个算法术语热词后 createEngine 报 code=601：
  E AI_TEXT: [CheckLexicons] lexicons length exceeds limit, length: 21
  W AI_TEXT: [ParseAsrEngineOptions] not system app! reset config to default
查证：文档说限「200 个 / 每个 2-20 字」，我的表 79 个 / 2-7 字完全合规。
所以 601 更可能来自「非系统应用不允许配热词」。
处理：去掉热词（只是优化项），热词表保留待真机再试。
